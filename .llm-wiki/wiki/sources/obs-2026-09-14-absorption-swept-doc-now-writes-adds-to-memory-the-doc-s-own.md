# 🔍 Observation: "Absorption" swept: doc now writes/adds to memory — the doc's own plain vocabulary

Phil challenged "absorption/absorbed" as non-software jargon: once defined it becomes a cornerstone term on which further unrecognisable descriptions build, forcing translation effort for the document's actual reader (a software engineer). Agreed and swept the term: it denoted nothing beyond "add to the memory set", and the doc already possessed the plain vocabulary (§10 Progressive path: "each hop may add evidence to memory, M_{k+1} ⊇ M_k"; Progressive Path gloss: "each hop writes its output to STM"). Replacements — doc: §10 loop "add the result to memory"; Def 17 "The terminal state is written into memory as a composed correspondence"; the granularity paragraph re-subjected ("The composed correspondence delivers…", "a lump in a written witness", "The written kline therefore holds…"); §11 "Klines written into memory carry their recorded depths"; worked example "written into memory as the composed correspondence". CONTEXT.md: Cogitation phase list now **select/derive/add/reenter**; Slot entry "The end state written into memory"; Progressive Path "the written end states". Probe aligned: flag expand_on_write, "write composed" trace line, policy labels "expand at write"/"lazy write", note "write-time expansion"; 7/7 PASS. "consume" retained (standard software usage, does real semantic work = use-as-evidence). "absorb" remains only in the two superseded legacy docs awaiting deletion and two incidental trainer.py comments — no action. Not committed.
