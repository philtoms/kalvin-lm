# ⭐ Observation: TRS spec sweep: rules state behaviour; prohibitions demoted to properties

Seventh round on docs/trs-significance.md: de-presumption sweep per user critique. The R3 anchoring paragraph ('E′ satisfies Definition 8 exactly. It is presented, never stored... never itself valued...') was deleted — it legislated prohibitions that are not rules (no rule says an R3-expanded kline cannot be stored or scored; behaviour is what rules DO: stores happen at R1, bands are assigned to candidates). R3 now states the anchor in one positive sentence: product is the entry kline E′, Definition 9 applies. Also removed 'There is no re-entry mechanism / §3 is the only consumer' editorialising. Swept the whole document for the same pattern (definitions/rules asserting what things AREN'T): Def 8 recast positively ('An entry's content reaches the domain through the S1 stores of its candidates; the entry locates neighbours; the candidates are what get valued'); D5/D6/D8/D10 rows reworded positive (D10 keeps the user's iff); R1 drops 'sole admission rule'; R2 drops 'decode_D is undefined... rewriting mints no signatures' gloss, keeps the S4 transition + misfit-asks sentence; R2a drops 'No rewrite occurs'; R3 occurrence paragraph drops 'no splice form / yields no candidate' clauses; R4 drops 'not a failed lookup' contrast; I-1 corollary drops 'not a separate axiom'; P-4 recast ('fabrication has no rule' — kept as property since non-existence is a property's job); preamble supersession note and 0.2 mapping row recast ('bands belong to candidates'). Remaining negatives audited as load-bearing: definitional contrasts (underfit/overfit), decode partiality, terminal conditions (R4), properties (P-1/P-3/P-4), set semantics, scope statements, changelog. Editorial principle established for this doc: rules state behaviour positively; prohibitions live only in properties (as observed consequences) or in user-ruled iff-statements.
