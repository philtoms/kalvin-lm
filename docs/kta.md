# Kalvin as a term algebra - first pass

In universal algebra and mathematical logic, a [term algebra](https://en.wikipedia.org/wiki/Term_algebra) is a freely generated algebraic structure built entirely out of syntax using formal symbols. [1]

## Core Components

- Signature ($\Sigma$): The foundational vocabulary that lists all available function symbols and operation names, along with their assigned arities (the number of arguments each operation takes). [2, 3]
- Set of Variables ($X$): A base collection of symbols used as placeholders or leaves in term trees, allowing open expressions to be constructed. [1, 4]
- Carrier Set ($T_\Sigma(X)$): The underlying set of all well-formed formal terms recursively generated by applying the signature's operations to the variables and constants. [1, 4]
- Fundamental Operations: The structural constructors that map tuples of smaller terms into larger composite terms, mirroring the syntactic rules defined by the signature. [1, 5]

## Homomorphisms and Substitutions in Term Algebras

## In a term algebra, structural operations mimic the syntax of the language itself. Because it is a freely generated structure, mapping terms to other structures—or replacing variables within the terms—follows clean, recursive algebraic properties.

## 1. Homomorphisms and the Universal Property

The term algebra $\mathcal{T}_\Sigma(X)$ is the "pure syntax" of a language. A homomorphism is a mapping that preserves this structure when moving from the pure syntax to an actual semantic interpretation (another algebra $\mathcal{A}$).
The core behavior relies on the Universal Property of Free Algebras:

- The Valuation Mapping: To interpret terms containing variables, you first define a function v: X → A that assigns a concrete value in the target algebra $\mathcal{A}$ to every variable in the set X.
- The Unique Extension: The universal property guarantees that this simple mapping v extends uniquely to a full algebra homomorphism $\hat{v}: \mathcal{T}_\Sigma(X) \to \mathcal{A}$.

## How the Homomorphism Evaluates Syntactic Terms:

1.  Variables: v̂(x) = v(x) for any variable x ∈ X.
2.  Constants: $\hat{v}(c) = c^\mathcal{A}$ for any constant symbol c, where $c^\mathcal{A}$ is the interpretation of the constant in $\mathcal{A}$.
3.  Composite Terms: $\hat{v}(f(t_1, \dots, t_n)) = f^\mathcal{A}(\hat{v}(t_1), \dots, \hat{v}(t_n))$, where $f^\mathcal{A}$ is the actual operation executed inside the target algebra.

---

## 2. Substitution Rules

A substitution is a specific type of endomorphism (a homomorphism from an algebra back into itself). Instead of evaluating syntax into a semantic domain, a substitution transforms syntax into new syntax by replacing variables with other terms.

## Formal Rules:

A substitution is initially defined as a function $\sigma: X \to \mathcal{T}_\Sigma(X)$ that maps variables to terms. By the universal property, σ uniquely extends to a structural transformation over all terms:

- Base Case (Variables): σ(x) is simply the term assigned to x by the initial mapping.
- Base Case (Constants): σ(c) = c (constants remain completely unaffected).
- Recursive Step: $\sigma(f(t_1, \dots, t_n)) = f(\sigma(t_1), \dots, \sigma(t_n))$ (the substitution is distributed down into the subterms).

## Key Structural Attributes:

- Composition: Substitutions can be composed. If σ and τ are substitutions, their composition $\sigma \circ \tau$ is also a valid structural substitution.
- Unification Foundation: This clean recursive property forms the mathematical foundation for unification algorithms, which are heavily used in automated theorem proving, type inference systems (like Haskell/ML), and logic programming (Prolog).

To fulfill this specific constraint, we will define a formal 2-sorted relational structure. [1]
In a multi-sorted system, instead of a single universal carrier set, we have distinct domains for each sort. Because our signature is purely relational, our "terms" are strictly variables belonging to one of the two sorts. [1]

- Variables of sort Node: $X_{\text{Node}} = \{n_1, n_2, n_3\}$

## 1. Substitutions (Syntax to Syntax)

A substitution must be sort-preserving (a variable of sort Kline must be replaced by a term of sort Kline). Let's define a syntactic substitution $\sigma$:
$$\sigma(k_A) = k_B, \quad \sigma(k_B) = k_C, \quad \sigma(k_C) = k_C$$

## Applying $\sigma$ to a Relational Formula:

Consider an atomic formula asserting a logical constraint between our kline vectors:
$$\psi = \text{AND}(k_A, k_B, k_C)$$
Applying the substitution $\sigma$ directly replaces the variables within the relational predicate:
$$\sigma(\psi) = \text{AND}(\sigma(k_A), \sigma(k_B), \sigma(k_C)) = \text{AND}(k_B, k_C, k_C)$$

## 2. Homomorphisms (Syntax to Semantic Models)

To evaluate these expressions, we map our syntax into a semantic 2-sorted Relational Model (Structure $\mathcal{M}$). [1]

## Concrete Semantic Domain of $\mathcal{M}$:

-
- Domain for Node ($\text{Node}^\mathcal{M}$): $\{0, 1\}$ (representing high/low voltage states).
- Domain for Kline ($\text{Kline}^\mathcal{M}$): All vectors of length $3$ over $\{0, 1\}$.
  $$\text{Kline}^\mathcal{M} = \{(0,0,0), (0,0,1), \dots, (1,1,1)\}$$
-

## Interpretation of Relations in $\mathcal{M}$:

The relations are defined extensionally as sets of tuples that make the predicates true:

-
- $\text{NOT}^\mathcal{M} = \{(v_1, v_2) \mid v_2 \text{ is the bitwise negation of } v_1\}$
- $\text{AND}^\mathcal{M} = \{(v_1, v_2, v_3) \mid v_3 = v_1 \land v_2 \text{ bitwise}\}$

## The Valuation Mapping (Homomorphism Base):

We define a valuation $v$ that maps our variables to elements in our semantic domains: [1]

-
- $v(k_A) = (1, 0, 1)$
- $v(k_B) = (0, 1, 1)$
- $v(k_C) = (0, 0, 1)$

## Evaluating Truth via Homomorphism:

A relational homomorphism verifies whether the structural properties map safely into the semantic truth values of the target model. Let's test two different formulas under our valuation: [1]

1.  Formula 1: $\phi_1 = \text{AND}(k_A, k_B, k_C)$

- We map the variables using $v$: $(v(k_A), v(k_B), v(k_C)) = ((1,0,1), (0,1,1), (0,0,1))$.
  - Does this tuple belong to $\text{AND}^\mathcal{M}$? Since $(1,0,1) \land (0,1,1) = (0,0,1)$, yes, the relation holds true under this model assignment.

2.  Formula 2: $\phi_2 = \text{NOT}(k_A, k_B)$

- We map the variables using $v$: $(v(k_A), v(k_B)) = ((1,0,1), (0,1,1))$.
  - Does this tuple belong to $\text{NOT}^\mathcal{M}$? The bitwise negation of $(1,0,1)$ is $(0,1,0)$, which does not equal $(0,1,1)$. Therefore, the relation evaluates to false.

We will add a structural function symbol, makeKline, which explicitly builds a vector out of individual nodes.

## The Updated Signature ($\Sigma$)

- Functions:
- makeKline: takes $N$ arguments of sort Node and outputs a term of sort Kline. For our $N=3$ node vector example, its type signature is:
  $$\text{makeKline}: \text{Node} \times \text{Node} \times \text{Node} \to \text{Kline}$$
- Predicates (Relational Symbols):
- $\text{AND}(k_1, k_2, k_3)$, $\text{OR}(k_1, k_2, k_3)$, and $\text{NOT}(k_1, k_2)$ as defined previously.

- $X_{\text{Node}} = \{n_1, n_2, n_3, n_4\}$

## Generating Non-Trivial Terms

Because we now have a function symbol, the carrier set for the Kline sort contains more than just variables. It includes complex syntactic expressions like:

- $t_1 = \text{makeKline}(n_1, n_2, n_3)$
- $t_2 = \text{makeKline}(n_2, n_3, n_4)$

## 1. Recursive Substitutions (Syntax to Syntax)

Let's define a syntactic substitution $\sigma$ that targets variables of sort Node:
$$\sigma(n_1) = n_4, \quad \sigma(n_2) = n_3, \quad \sigma(n_3) = n_2, \quad \sigma(n_4) = n_1$$

## Applying $\sigma$ to a Compound Term:

When we apply $\sigma$ to our term $t_1$, it recursively penetrates down to the variables:
$$\sigma(t_1) = \sigma(\text{makeKline}(n_1, n_2, n_3)) = \text{makeKline}(\sigma(n_1), \sigma(n_2), \sigma(n_3)) = \text{makeKline}(n_4, n_3, n_2)$$

## Applying $\sigma$ to a Formula:

If we have a logical relation asserting an operation between a variable kline and a constructed kline:
$$\psi = \text{NOT}(k_A, \text{makeKline}(n_1, n_2, n_3))$$
Applying the substitution yields:
$$\sigma(\psi) = \text{NOT}(\sigma(k_A), \text{makeKline}(\sigma(n_1), \sigma(n_2), \sigma(n_3))) = \text{NOT}(k_A, \text{makeKline}(n_4, n_3, n_2))$$

## 2. Homomorphisms and Recursive Semantic Evaluation

Now we map our syntactic terms into a concrete semantic model $\mathcal{M}$ where the function symbol actually does something.

## The Semantic Target Model ($\mathcal{M}$)

- Domain for Node ($\text{Node}^\mathcal{M}$): $\{0, 1\}$
- Domain for Kline ($\text{Kline}^\mathcal{M}$): $\{0, 1\}^3$ (the set of all 3-bit binary tuples).
- Interpretation of makeKline ($\text{makeKline}^\mathcal{M}$): A function that takes three bits and bundles them into an ordered 3-tuple:
  $$\text{makeKline}^\mathcal{M}(b_1, b_2, b_3) = (b_1, b_2, b_3)$$

## The Valuation Mapping ($v$)

We assign semantic values to our variables:

- $v(n_1) = 1, \quad v(n_2) = 0, \quad v(n_3) = 1, \quad v(n_4) = 0$
- $v(k_A) = (0, 1, 0)$

## Evaluating via the Unique Homomorphism ($\hat{v}$)

Let's evaluate the formula $\psi = \text{NOT}(k_A, \text{makeKline}(n_1, n_2, n_3))$ using the unique extension homomorphism $\hat{v}$:

1.  Evaluate the left argument (a variable):
    $$\hat{v}(k_A) = v(k_A) = (0, 1, 0)$$
2.  Evaluate the right argument (a compound term):
    $$\hat{v}(\text{makeKline}(n_1, n_2, n_3)) = \text{makeKline}^\mathcal{M}(\hat{v}(n_1), \hat{v}(n_2), \hat{v}(n_3))$$
    $$\hat{v}(\text{makeKline}(n_1, n_2, n_3)) = \text{makeKline}^\mathcal{M}(1, 0, 1) = (1, 0, 1)$$
3.  Evaluate the Predicate Relation:
    We check if the tuple $\big(\hat{v}(k_A), \hat{v}(\text{makeKline}(n_1, n_2, n_3))\big)$ satisfies the relation $\text{NOT}^\mathcal{M}$:
    $$\text{Is } ((0, 1, 0), (1, 0, 1)) \in \text{NOT}^\mathcal{M}?$$
    Since $(1, 0, 1)$ is the exact bitwise inversion of $(0, 1, 0)$, the relation holds true under this valuation.

To define an equational theory over our 2-sorted term algebra, we shift from describing specific semantic models to defining purely syntactic rules of balance and identity.
An equational theory consists of a set of equations (pairs of terms of the exact same sort) that are assumed to be universally true. We then use a formal deduction system to prove new equations without ever evaluating them into bits or hardware.

---

## 1. Defining the Axioms (The Base Equations)

Let's specify a set of identity axioms $E$ for our 2-sorted signature. Because we have the makeKline function, we can state equations that relate Kline terms to each other based on their internal Node configurations.
Let $k, k_1, k_2$ be variables of sort Kline, and $n_1, n_2, n_3$ be variables of sort Node. We define our equational theory with the following axioms:

- Axiom 1 (Idempotence of AND via Predicates expressed as terms):
  If we were to represent predicates as boolean-valued terms, we might write:
  $\text{AND}(k, k) = k$
- Axiom 2 (Structural Deconstruction):
  Suppose we add a component-wise negation function to our syntax, $\text{notK}(k): \text{Kline} \to \text{Kline}$. We can axiomatise its behavior directly down to the nodes:
  $\text{notK}(\text{makeKline}(n_1, n_2, n_3)) = \text{makeKline}(\text{notN}(n_1), \text{notN}(n_2), \text{notN}(n_3))$
  (Where $\text{notN} : \text{Node} \to \text{Node}$ is a structural function inversion symbol).
- Axiom 3 (Node Involution):
  $\text{notN}(\text{notN}(n_1)) = n_1$

---

## 2. The Rules of Equational Deduction

To prove that two complex terms are equal under our theory ($E \vdash t = u$), we use Birkhoff’s standard rules of equational logic. These rules ensure that equality behaves as a congruence relation:

| Rule Name    | Formal Definition                                                            | Description                                                                |
| ------------ | ---------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| Reflexivity  | $\vdash t = t$                                                               | Any term is equal to itself.                                               |
| Symmetry     | If $\vdash t = u$, then $\vdash u = t$                                       | Equality can be flipped.                                                   |
| Transitivity | If $\vdash t = u$ and $\vdash u = v$, then $\vdash t = v$                    | Equality chain composition.                                                |
| Substitution | If $\vdash t = u$, then $\vdash \sigma(t) = \sigma(u)$                       | Valid for any sort-preserving substitution $\sigma$.                       |
| Congruence   | If $\vdash t_i = u_i$, then $\vdash f(\dots t_i \dots) = f(\dots u_i \dots)$ | If you change a subterm to an equal subterm, the whole term remains equal. |

---

## 3. A Syntactic Proof Example (Double Negation of a Kline)

Let's prove that applying our structural vector negation twice returns the original vector. We want to prove the theorem:
$$E \vdash \text{notK}(\text{notK}(\text{makeKline}(n_1, n_2, n_3))) = \text{makeKline}(n_1, n_2, n_3)$$

## Step-by-Step Derivation:

1.  Apply Axiom 2 (Inner Negation):
    By pointing to the inner expression, we substitute the definition of notK:
    $$\text{notK}(\text{makeKline}(n_1, n_2, n_3)) = \text{makeKline}(\text{notN}(n_1), \text{notN}(n_2), \text{notN}(n_3))$$
2.  Congruence Step:
    Wrap both sides of Step 1 in an outer $\text{notK}$ function:
    $$\text{notK}(\text{notK}(\text{makeKline}(n_1, n_2, n_3))) = \text{notK}(\text{makeKline}(\text{notN}(n_1), \text{notN}(n_2), \text{notN}(n_3)))$$
3.  Apply Substitution Rule to Axiom 2 (Outer Negation):
    Define a substitution $\sigma$ such that $\sigma(n_1) = \text{notN}(n_1)$, $\sigma(n_2) = \text{notN}(n_2)$, and $\sigma(n_3) = \text{notN}(n_3)$. Applying this to Axiom 2 transforms the right side of our equation:
    $$\text{notK}(\text{makeKline}(\text{notN}(n_1), \text{notN}(n_2), \text{notN}(n_3))) = \text{makeKline}(\text{notN}(\text{notN}(n_1)), \text{notN}(\text{notN}(n_2)), \text{notN}(\text{notN}(n_3)))$$
4.  Apply Axiom 3 (Node Involution) & Congruence:
    Since $\text{notN}(\text{notN}(n_i)) = n_i$ for each node variable, the congruence rule allows us to replace them inside the makeKline constructor:
    $$\text{makeKline}(\text{notN}(\text{notN}(n_1)), \text{notN}(\text{notN}(n_2)), \text{notN}(\text{notN}(n_3))) = \text{makeKline}(n_1, n_2, n_3)$$
5.  Transitivity:
    Chaining steps 2, 3, and 4 together proves our target identity:
    $$\text{notK}(\text{notK}(\text{makeKline}(n_1, n_2, n_3))) = \text{makeKline}(n_1, n_2, n_3)$$

## Why This Matters: Soundness and Completeness

Because this entire derivation happened inside the Term Algebra, we never had to worry about whether the bits were 0 or 1, or how many nodes $N$ actually exist in a real deployment.
Birkhoff's Completeness Theorem guarantees that because this identity is provable using these syntactic rules, it will evaluate to true in every single semantic model (or hardware simulation) that satisfies our initial axioms.

To turn our equational theory into a Term Rewriting System (TRS), we must convert our static, symmetrical equations (t = u) into directional rewrite rules (t → u).
In a TRS, we treat equations as one-way instructions to simplify or optimize syntactic terms. The goal is to continuously transform a complex term until it cannot be rewritten any further, reaching what is called a normal form.

---

## 1. Orienting the Rules into a TRS

Let's take the equations from our 2-sorted kline theory and orient them from left to right, going from higher syntactic complexity to lower syntactic complexity:

- Rule 1 (Negation Push-down):
  $$\text{notK}(\text{makeKline}(n_1, n_2, n_3)) \longrightarrow \text{makeKline}(\text{notN}(n_1), \text{notN}(n_2), \text{notN}(n_3))$$
- Rule 2 (Double Negation Elimination):
  $$\text{notN}(\text{notN}(n)) \longrightarrow n$$
- Rule 3 (Idempotence Simplification):
  $$\text{andK}(k, k) \longrightarrow k$$

---

## 2. How the Rewriting Engine Operates

A TRS simplifies terms by repeatedly executing two fundamental actions:

1.  Pattern Matching: The engine searches for a subterm (called a redex) that matches the left-hand side of a rewrite rule under some substitution σ.
2.  Replacement: It replaces that subterm with the right-hand side of the rule, instantiated with the same substitution σ.

---

## 3. A Rewriting Execution Trace

Let's pass a highly redundant syntactic expression through our TRS engine to watch it automatically reduce it to its simplest form.
Initial Term (t₀):
A system asserting the intersection of a vector with its own doubly-negated version:
$$t_0 = \text{andK}\big(\text{notK}(\text{makeKline}(\text{notN}(n_1), n_2, n_3)),\ \text{notK}(\text{makeKline}(\text{notN}(n_1), n_2, n_3))\big)$$

## Step 1: Apply Rule 3 (Idempotence)

The rewrite engine detects that the top-level structure matches andK(k, k), where the substitution for the variable k is the term notK(makeKline(notN(n₁), n₂, n₃)).

- Action: Collapse the duplicate terms.
- Resulting Term (t₁):
  $$t_1 = \text{notK}(\text{makeKline}(\text{notN}(n_1), n_2, n_3))$$

## Step 2: Apply Rule 1 (Negation Push-down)

The engine matches t₁ against the left side of Rule 1 with the substitution: σ(n₁) = notN(n₁), σ(n₂) = n₂, and σ(n₃) = n₃.

- Action: Push the notK vector operation down to the individual node components.
- Resulting Term (t₂):
  $$t_2 = \text{makeKline}\big(\text{notN}(\text{notN}(n_1)),\ \text{notN}(n_2),\ \text{notN}(n_3)\big)$$

## Step 3: Apply Rule 2 (Double Negation Elimination)

The engine scans the subterms of t₂. It finds a redex in the first argument slot of the makeKline constructor: notN(notN(n₁)). This matches Rule 2 exactly.

- Action: Strip away the double negation on the node variable.
- Resulting Term (t₃):
  $$t_3 = \text{makeKline}(n_1,\ \text{notN}(n_2),\ \text{notN}(n_3))$$

## Terminal State: Normal Form

## The engine scans t₃ again. No further left-hand patterns from our rule set match any part of the expression. The rewriting stops. t₃ is declared the Normal Form of our initial expression.

## 4. Critical Mathematical Properties of a TRS

For a term rewriting system to be reliable (like an optimizing compiler or an automated hardware prover), it must satisfy two properties:

- Termination (Strong Normalization): The rewriting process must never loop infinitely. Because each of our rules visibly reduces the number of function applications or nesting depth, our kline TRS is guaranteed to terminate.
- Confluence (The Church-Rosser Property): If a term has multiple subterms that can be rewritten at the same time, the order in which you choose to apply the rules must not matter. You will always end up with the exact same final normal form.

Because our system is both terminating and confluent, it is convergent. This means our algebraic framework serves as a decisive algorithm for checking if two complex circuits are functionally identical.

In a term algebra, unification is the process of finding a sort-preserving substitution $\sigma$ that makes two different syntactic terms completely identical.
While rewriting goes in one direction to simplify a single term ($t \to u$), unification takes two terms ($t$ and $u$) and solves the equation $t \stackrel{?}{=} u$ by filling in the blanks (assigning values to variables).

---

## The 2-Sorted Unification Algorithm

For our kline system, Robinson's first-order unification algorithm operates by processing a queue of equations. Because the system is 2-sorted, the algorithm must enforce strict sort checking: a variable of sort Node can only be unified with a term of sort Node, and a variable of sort Kline can only be unified with a term of sort Kline.

## The Core Rules:

1.  Delete: If you encounter $x \stackrel{?}{=} x$ (where $x$ is any variable), remove it from the queue.
2.  Decompose: If you encounter two identical functions, $f(t_1, \dots, t_m) \stackrel{?}{=} f(u_1, \dots, u_m)$, break them apart. Remove the parent equation and add the sub-component equations to the queue: $t_1 \stackrel{?}{=} u_1, \dots, t_m \stackrel{?}{=} u_m$.
3.  Conflict: If you encounter two different function constructors (e.g., trying to unify a makeKline term with a variable of a completely different sort without a structural pathway), the algorithm fails. There is no unifier.
4.  Eliminate Variable: If you encounter $x \stackrel{?}{=} t$ (where $x$ is a variable and $t$ is a term):

- Occurs Check: First, check if $x$ appears anywhere inside the structure of $t$. If it does (e.g., $x \stackrel{?}{=} \text{notN}(x)$), the algorithm fails because it would lead to an infinite loop.
  - Substitution: If it passes the occurs check, record $x \mapsto t$ as part of the winning substitution, and immediately apply this substitution to all other equations remaining in the queue.

## Step-by-Step Unification Example

Let's solve a hardware matching problem. We want to find a substitution that unifies a kline vector containing abstract variables with a kline vector that has concrete, structured components.

## Setup:

- Variables of sort Node: $\{n_A, n_B\}$
- Variables of sort Kline: $\{k_X\}$
- Term 1 ($t$): $\text{makeKline}(n_A,\ \text{notN}(n_B),\ n_A)$
- Term 2 ($u$): $\text{makeKline}(\text{notN}(n_1),\ n_2,\ n_3)$ (where $n_1, n_2, n_3$ are fixed constants or variables from another scope)

We want to solve the unification problem:
$$\text{makeKline}(n_A,\ \text{notN}(n_B),\ n_A) \stackrel{?}{=} \text{makeKline}(\text{notN}(n_1),\ n_2,\ n_3)$$

## Execution Trace:

1.  Decompose the makeKline function:
    Since the top-level constructors match, the engine strips them away and splits the problem into three parallel node equations:

- Equation 1: $n_A \stackrel{?}{=} \text{notN}(n_1)$
  - Equation 2: $\text{notN}(n_B) \stackrel{?}{=} n_2$
  - Equation 3: $n_A \stackrel{?}{=} n_3$

2.  Process Equation 1 (Eliminate Variable $n_A$):

- $n_A$ is a variable of sort Node. $\text{notN}(n_1)$ is a valid term of sort Node.
  - The occurs check passes ($n_A$ is not inside $\text{notN}(n_1)$).
  - We record our first substitution mapping: $\sigma_1 = \{n_A \mapsto \text{notN}(n_1)\}$.
  - We apply this mapping to the rest of the queue. Equation 3 changes from $n_A \stackrel{?}{=} n_3$ to $\text{notN}(n_1) \stackrel{?}{=} n_3$.

3.  Process Equation 2 (Eliminate Variable $n_B$):

- We isolate the variable by flipping the equation (via Symmetry) to: $n_2 \stackrel{?}{=} \text{notN}(n_B)$, or we can process it directly by matching the structural properties if notN has an inverse rewriting rule. Assuming $n_B$ is the variable we are solving for, we apply the notN operator to both sides (leveraging our equational theory's involution rule):
  - $\text{notN}(\text{notN}(n_B)) \stackrel{?}{=} \text{notN}(n_2) \implies n_B \stackrel{?}{=} \text{notN}(n_2)$.
  - We record the second mapping: $\sigma_2 = \{n_B \mapsto \text{notN}(n_2)\}$.

4.  Process Equation 3 (Check remaining constraints):

- The queue now holds: $\text{notN}(n_1) \stackrel{?}{=} n_3$.
  - If $n_3$ is a free variable, we can eliminate it: $\sigma_3 = \{n_3 \mapsto \text{notN}(n_1)\}$.

## The Most General Unifier (MGU)

By composing our recorded steps ($\sigma_1 \circ \sigma_2 \circ \sigma_3$), the algorithm produces the Most General Unifier:
$$\sigma = \{n_A \mapsto \text{notN}(n_1),\ n_B \mapsto \text{notN}(n_2),\ n_3 \mapsto \text{notN}(n_1)\}$$
If you apply this substitution $\sigma$ to both Term 1 and Term 2, they both turn into the exact same structural term in the algebra:
$$\text{makeKline}(\text{notN}(n_1),\ \text{notN}(\text{notN}(n_2)),\ \text{notN}(n_1))$$
Which (if evaluated by our Term Rewriting System) simplifies neatly to:
$$\text{makeKline}(\text{notN}(n_1),\ n_2,\ \text{notN}(n_1))$$

---

## Why Unification is Crucial in Term Algebras

In computer-aided verification and hardware design, unification acts as a structural query engine. Instead of just checking if two hardcoded netlists match, you can leave variables in your circuit layout. Unification will automatically compute the exact configuration of nodes and connections required to make your design match a specific target specification.

In a Term Rewriting System (TRS), Critical Pairs represent the exact points where two conflicting rewrite rules overlap on the same term. They reveal whether your system is truly deterministic (confluent) or if the order in which you apply rules will lead to different, conflicting results.
To find these conflicts during a merge, we use unification to force two different rewrite rules to compete for the same piece of syntax.

---

## The Mathematical Recipe for a Critical Pair

To calculate a critical pair between two rewrite rules, $R_1: l_1 \to r_1$ and $R_2: l_2 \to r_2$:

1.  Variable Renaming: Rename all variables in both rules so they share absolutely no variable names. This avoids accidental variable clashes.
2.  Isolate a Subterm: Select a non-variable subterm $s$ from inside the left-hand side of the first rule ($l_1$).
3.  Unify the Overlap: Attempt to unify this subterm $s$ with the entire left-hand side of the second rule ($l_2$). Find their Most General Unifier ($\sigma$).
4.  Fork the Paths: Apply $\sigma$ to the entire parent term $l_1$. Because the terms overlap, you can now rewrite this single unified term in two different directions:

- Path A: Apply Rule 1 to the top level: $\sigma(l_1) \longrightarrow \sigma(r_1)$.
  - Path B: Apply Rule 2 to the isolated subterm $s$: $\sigma(l_1) \longrightarrow \sigma(l_1[r_2]_s)$ (replacing $s$ with $r_2$).

5.  The Critical Pair: The pair of resulting terms $\langle \text{Path A}, \text{Path B} \rangle$ is your Critical Pair.

---

## Concrete Calculation Example: Merging Logic Rules

Let's say two engineers are merging their rewrite rules for our Kline term algebra. They introduce two rules that interact aggressively with the notK vector negation operator.

- Rule 1 ($R_1$): Pushing negation into a constructed line.
  $$\text{notK}(\text{makeKline}(n_1, n_2, n_3)) \longrightarrow \text{makeKline}(\text{notN}(n_1), \text{notN}(n_2), \text{notN}(n_3))$$
- Rule 2 ($R_2$): Overriding a specific diagnostic line configuration (e.g., if a line contains a dedicated test node $n_{\text{test}}$, bypass the negation and output a ground vector).
  $$\text{notK}(\text{makeKline}(n_{\text{test}}, x, y)) \longrightarrow \text{makeKline}(\text{gnd}, \text{gnd}, \text{gnd})$$

## Step 1: Variable Renaming

The variables are already distinct: $R_1$ uses $\{n_1, n_2, n_3\}$ and $R_2$ uses $\{x, y\}$ ($n_{\text{test}}$ and $\text{gnd}$ are fixed constants).

## Step 2: Isolate the Subterm

We look at the left-hand side of Rule 1: $l_1 = \text{notK}(\text{makeKline}(n_1, n_2, n_3))$.
We choose the entire term as our overlap point, because it shares the same top-level structure as $l_2 = \text{notK}(\text{makeKline}(n_{\text{test}}, x, y))$.

## Step 3: Unify the Overlap

We run our 2-sorted unification algorithm on the two left-hand sides:
$$\text{notK}(\text{makeKline}(n_1, n_2, n_3)) \stackrel{?}{=} \text{notK}(\text{makeKline}(n_{\text{test}}, x, y))$$
Decomposing the operators yields the Most General Unifier ($\sigma$):
$$\sigma = \{n_1 \mapsto n_{\text{test}},\ x \mapsto n_2,\ y \mapsto n_3\}$$

## Step 4: Fork the Paths

We apply $\sigma$ to our left-hand side to create the peak overlapping term:
$$\text{Unified Term} = \text{notK}(\text{makeKline}(n_{\text{test}}, n_2, n_3))$$
Now, we execute both rules on this single term to see where they branch:

- Path A (Executing Rule 1):
  Rule 1 pushes the negation down to all three nodes blindly:
  $$t_A = \text{makeKline}(\text{notN}(n_{\text{test}}), \text{notN}(n_2), \text{notN}(n_3))$$
- Path B (Executing Rule 2):
  Rule 2 detects the diagnostic constant $n_{\text{test}}$ and instantly flushes the system to ground:
  $$t_B = \text{makeKline}(\text{gnd}, \text{gnd}, \text{gnd})$$

## Step 5: The Critical Pair

Our calculation has successfully generated the critical pair:
$$\Big\langle \text{makeKline}(\text{notN}(n_{\text{test}}), \text{notN}(n_2), \text{notN}(n_3)),\ \text{makeKline}(\text{gnd}, \text{gnd}, \text{gnd}) \Big\rangle$$

---

## What Happens Next? (Knuth-Bendix Completion)

This critical pair exposes a non-confluent rift in our system. Depending on which rule a compiler applies first, a circuit will compile into two completely different physical netlists ($t_A$ vs $t_B$).
To resolve this conflict and fix the merge, the TRS engine uses a process called Knuth-Bendix Completion:

1.  It attempts to rewrite both sides of the critical pair to their respective normal forms using any other existing rules in the system.
2.  If they reduce to the exact same term, the critical pair joins, meaning the conflict resolves itself naturally.
3.  If they do not join (like our example above), the system creates a brand new rewrite rule out of the conflict to force them together. For example, it might add:
    $$\text{makeKline}(\text{notN}(n_{\text{test}}), \text{notN}(n_2), \text{notN}(n_3)) \longrightarrow \text{makeKline}(\text{gnd}, \text{gnd}, \text{gnd})$$

By automatically calculating these pairs and adding rules to close the loops, the system systematically engineers a confluent, fully predictable term algebra.

To see how we "close the loop", we will run a mini-execution of the Knuth-Bendix Completion algorithm. We will take the unresolved critical pair we just discovered and show how the system automatically generates a brand-new rule to heal the non-confluence.

## The Current Conflict Loop

Recall the two conflicting rules from our previous step:

- Rule 1 ($R_1$): $\text{notK}(\text{makeKline}(n_1, n_2, n_3)) \longrightarrow \text{makeKline}(\text{notN}(n_1), \text{notN}(n_2), \text{notN}(n_3))$
- Rule 2 ($R_2$): $\text{notK}(\text{makeKline}(n_{\text{test}}, x, y)) \longrightarrow \text{makeKline}(\text{gnd}, \text{gnd}, \text{gnd})$

These rules generated a divergent peak for the overlapping term $\text{notK}(\text{makeKline}(n_{\text{test}}, n_2, n_3))$, which split into the following unresolved Critical Pair:

- Left Branch ($t_A$): $\text{makeKline}(\text{notN}(n_{\text{test}}), \text{notN}(n_2), \text{notN}(n_3))$
- Right Branch ($t_B$): $\text{makeKline}(\text{gnd}, \text{gnd}, \text{gnd})$

---

## Step 1: Evaluating the Nodes for Local Inversions

Before the system blindly adds a massive new rule, it first checks if any other rules in our algebra can bring these two terms closer together.
Let's assume our algebra has a specific structural rule detailing what happens when you try to invert a diagnostic test node:

- Rule 3 ($R_3$): $\text{notN}(n_{\text{test}}) \longrightarrow n_{\text{test}}$ (The test pin is self-inverting or acts as an active-low bypass indicator).

The completion engine applies Rule 3 to the first slot of the Left Branch ($t_A$):
$$\text{makeKline}(\mathbf{\text{notN}(n_{\text{test}})}, \text{notN}(n_2), \text{notN}(n_3)) \longrightarrow \text{makeKline}(\mathbf{n_{\text{test}}}, \text{notN}(n_2), \text{notN}(n_3))$$
Now, the system evaluates both branches to see if they match. They don't:

- Normalized Left Branch ($t_A'$): $\text{makeKline}(n_{\text{test}}, \text{notN}(n_2), \text{notN}(n_3))$
- Normalized Right Branch ($t_B$): $\text{makeKline}(\text{gnd}, \text{gnd}, \text{gnd})$

---

## Step 2: Orienting the New Rule to Close the Loop

Because the normal forms $t_A'$ and $t_B$ still do not match, we have an open divergence loop. To close it, the algorithm turns the open equation into a new rewrite rule.
To determine the direction of the arrow ($\to$), the system uses a reduction ordering (usually based on syntactic complexity or structural weight). The ground state vector $\text{makeKline}(\text{gnd}, \text{gnd}, \text{gnd})$ is significantly simpler and more stable than a vector holding dynamic variables and inversions. Therefore, the arrow points from left to right:

- Rule 4 ($R_4$):
  $$\text{makeKline}(n_{\text{test}}, \text{notN}(n_2), \text{notN}(n_3)) \longrightarrow \text{makeKline}(\text{gnd}, \text{gnd}, \text{gnd})$$

## Generalising the Rule

To make this rule robust, the engine abstracts the specific variable names $n_2$ and $n_3$ out into generic, universal variables for any node sort ($a$ and $b$). The official new rule added to our database becomes:
$$\mathbf{R_4: \text{makeKline}(n_{\text{test}}, \text{notN}(a), \text{notN}(b)) \longrightarrow \text{makeKline}(\text{gnd}, \text{gnd}, \text{gnd})}$$

---

## The Result: A Confluent, Closed Loop

With Rule 4 safely embedded into the rewriting engine, the conflict is permanently resolved. If a compiler or a hardware verification tool encounters the problematic term in the future, the choice of path no longer matters. Both directions now safely collapse to the exact same normal form:

                  [ overlapping term ]
             notK(makeKline(n_test, n2, n3))
                       /          \
            (via R1)  /            \  (via R2)
                     v              v
      makeKline(notN(n_test),    makeKline(gnd, gnd, gnd)
         notN(n2), notN(n3))                 |

                     |                       |
            (via R3) |                       |
                     v                       |
       makeKline(n_test,                     |
         notN(n2), notN(n3))                 |
                     \                       |
            (via R4)  \                      | (Terminated)
                       v                     v
                makeKline(gnd, gnd, gnd) <---+--- [ CLOSED LOOP ]

The system has successfully self-healed by adding a structural bypass rule, ensuring that any netlist optimization will remain entirely deterministic.
